# Cognitive, timing, and input

## Rules

- Use concise labels, instructions, and error text that says what happened and how to recover. Keep essential help in a consistent relative location (3.2.6).
- Do not make instructions depend only on shape, color, size, visual location, orientation, or sound. Name the control or information as well (1.3.3).
- Do not trigger a major context change merely because a control receives focus or a value changes. Tell users before behavior changes context (3.2.1, 3.2.2).
- Warn before a session or task timeout, state the remaining time, and let users extend it unless the timing is essential or otherwise excepted (2.2.1).
- Provide pause, stop, or hide controls for moving, blinking, scrolling, or auto-updating content that meets 2.2.2 conditions. `prefers-reduced-motion` does not replace these controls.
- For legal, financial, test-response, or user-controlled data submissions, provide reversal, input checking, or review/confirmation as required by 3.3.4.
- Do not ask users to re-enter information already supplied in the same process unless an exception applies (3.3.7).
- Authentication must not rely on a cognitive-function test without an alternative or assistance mechanism. Allow paste, password managers, and accessible authentication methods (3.3.8).
- Preserve consistent navigation and identification for repeated controls across routes (3.2.3, 3.2.4).
